## 1. 定位与目标

总提案的主线是"FPGA 纯硬件推理扩散模型"。本子项目是整条主线的**第一个子项目**，职责是在 PC 上把算法层彻底跑通并沉淀为后续所有硬件工作的"规格来源"。

核心思想：**渐进逼近硬件的四级阶梯**，每一级都是下一级的黄金参考，出问题可精确二分定位。

| 级别 | 内容 | 产出 |
|---|---|---|
| L0 | diffusers 高级 API 跑 fp32 基线采样 | 画质基线、Go/No-go 数据 |
| L1 | 全手写 UNet 前向 + 手写 DDIM 采样器（不调用 `UNet2DModel.forward`） | 逐层显式可见的"真实规格" |
| L1.5 | 注意力消融实验 | RTL 是否需要注意力块的结论 |
| L2 | PTQ INT8 + 算子级位真定点模拟器 | 量化权重、常数表、黄金向量 |

### 1.1 成功标准

1. `google/ddpm-cat-256` 在**原生 256×256** 分辨率下采样的画质通过人工验收（"认得出是猫"）（v1.1 修订：64×64 与 128×128 跨分辨率已被 F1 对照实验证伪，主线切原生 256×256，决策记录见总提案 §4.2）；
2. 手写 UNet 前向与 diffusers 参考实现对齐（§5.2 容差）；
3. 注意力消融实验给出明确 Go/No-go 结论；
4. INT8 位真模拟器采样画质通过人工验收，且与 PyTorch 量化参考逐比特对齐；
5. 导出硬件就绪的全部 artifact：`weights.bin`、层描述符、DDIM 常数表、FiLM 表、ModelSim 黄金向量。

### 1.2 非目标

- 任何 RTL / FPGA 相关工作（M1 及以后）；
- 任何训练或微调（微调仅为总提案 §4.4 的例外预案，不在本 spec 内）；
- UART/网络权重加载脚本（M3）；导出格式需为其预留，但不实现；
- 数据流级硬件模拟（分块、行缓冲不在本期范围，见 §4 决策 D3）。

## 2. 环境与工程约束

- **Python**：3.11+，uv + `pyproject.toml` 管理依赖，`uv sync` 一键复现；
- **硬件**：**仅 CPU**（无本地 GPU）。所有采样脚本必须：
  - 支持 `--num-samples` 控制规模与断点续跑；
  - 默认样本数按 CPU 可承受设计（画质关卡 20 张，见 §5.1）；
  - 不 import 任何 CUDA 相关路径导致 CPU-only 环境报错；
- **主要依赖**：`torch`（CPU 版）、`diffusers`、`numpy`、`pillow`、`pytest`、`huggingface-hub`。位真模拟器只用 numpy（不依赖 torch 的整型语义），保证确定性；
- **测试**：pytest，`uv run pytest` 全绿是每个 feature 分支合入 main 的前置条件；
- **随机性**：所有采样入口接受显式 seed，测试与验收实验全部固定 seed 可复现。

## 4. 已确认的关键决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | spec 粒度 | 按子项目拆分，本 spec 只覆盖 M0 | 全项目远超单 spec 合理粒度；每个里程碑独立走 spec→plan→实现 |
| D2 | L1 复现深度 | 全手写 UNet 前向，加载官方权重 | 每层算子/张量形状/系数显式可见，是定点化与 RTL 的唯一规格来源；hook 方案对 diffusers 内部不透明 |
| D3 | 位真模拟器保真度 | 算子级（非数据流级） | 数值行为逐比特复现（INT8 乘、INT32 累加、移位重整、截位饱和），但不模拟分块/行缓冲；平衡工作量与 M2 调试收益 |
| D4 | 画质验收 | 人工验收，样本 20 张（CPU 约束：64×64 每张约 8s；**256×256 每张约 2 分钟**，20 张约 40 分钟，可接受）（v1.1 修订） | 人眼判断"是不是猫"；批量任务夜间跑 |

## 5. 技术要求

### 5.1 L0 fp32 基线（F1）

- 用 diffusers 加载 `google/ddpm-cat-256` 与 `jfjensen/sd-class-butterflies-64`，DDIM（η=0）采样；**蝴蝶模型 @64×64（原生），猫模型 @256×256（原生）**（v1.1 修订：跨分辨率已证伪）；
- 采样步数参数化；猫模型需同时产出 **DDIM-50 与 DDIM-20 两组** 20 张样本，供演示默认步数决策（总提案风险 1b）；
- 产出：`artifacts/` 下按模型/seed 组织的样本图（PNG 拼图 + 单图）、一份采样元数据（seed、步数、耗时）；
- **画质关卡**：猫模型 @256×256 各组 20 张人工验收，结论写入验收报告（通过 / 触发总提案 §4.4 备选路径）。**未通过则项目暂停，回到方向讨论**。
- v1.1 备注：F1 已执行的 64×64 批次与对照实验（64/128/256）作为决策证据保留在 `artifacts/f1/` 与 `artifacts/debug/`，报告中引用。

### 5.2 L1 手写复现（F2）

- 手写 `nn.Module` 实现 UNet2D 全部构件：conv3×3、下/上采样、GroupNorm、SiLU、残差块、注意力块、时间步 FiLM 注入；加载 `ddpm-cat-256` 官方权重（含权重名映射）。注意该模型 config 的两个非默认值：`freq_shift=1`、`flip_sin_to_cos=false`（见 `docs/reference/unet-config-ddpm-cat-256.json`），手写时间嵌入必须一致（v1.1 补充）；
- 手写 DDIM 采样器（η=0），不调用 diffusers scheduler；
- 对齐标准（fp32，固定 seed、固定初始噪声）：
  - 逐层中间输出与 diffusers hook 抓取的参考值对齐：相对误差 < 1e-4；开发期可在 64×64 输入上做逐层对齐（快），**但至少一次完整前向与一次完整 DDIM-3 步采样必须在 256×256 输入上对齐**（v1.1 修订，确保主线路径被覆盖）；
  - 最终采样图像：逐像素最大绝对差 < 2e-3，且人眼无可见差异；
- 逐层中间结果可导出（npy），供 L2 与后续 RTL 对照。

### 5.3 L1.5 注意力消融（F3）

- 在手写模型上构造去注意力变体（注意力块替换为恒等/直通，保持张量形状不变）；
- 同 seed 对比采样：原模型 vs 去注意力，各 20 张，**在 256×256 下进行**（v1.1 修订：256 下注意力层工作分辨率为 block5 16×16 / mid 8×8，与 64 输入时的 4×4/2×2 完全不同，任何 64×64 的消融直觉都不可沿用）；
- 产出对比报告与明确结论：**Go**（RTL 不实现注意力，F4 起按无注意力网络走）/ **No-go**（保留注意力，注意力 RTL 进主线排期）；
- 结论由项目负责人签字确认后合入。

### 5.4 L2 量化与导出（F4）

- PTQ INT8：权重 per-channel 对称量化；激活按"步组"静态标定（DDIM-50 分 4~8 组，每组一套 scale），标定数据来自 L1 模型在固定 seed 集上的激活统计。**标定在 256×256 下进行**；CPU 上每次 256 前向约 2~3 秒，标定集规模控制在 8~16 个样本 × 每步组，必要时只在代表性时间步上采集（v1.1 补充）；
- 量化方案参数（组数、per-channel/per-tensor、饱和策略）集中在一个配置文件中，可复现实验；
- 用 PyTorch 浮点模拟量化（fake-quant 参考）先验证画质：INT8 采样 20 张人工验收；
- 导出（格式在本 feature 的 plan 中冻结，写入 `docs/` 格式说明）：
  - `weights.bin`（INT8 权重 + per-channel scale）；
  - 层描述符表（cin/cout/stride/pad/算子类型/标度索引）；
  - DDIM 常数表（√ᾱ 序列，定点化）；
  - FiLM 表（各时间步 per-channel scale/shift，定点化）。

### 5.5 L2 位真模拟器与黄金向量（F5）

- numpy 实现的算子级位真定点模拟器：逐算子复现目标 RTL 数值行为——INT8×INT8 乘、INT32 累加、per-channel 移位重整、截位与饱和；Q 格式定义集中在 `quant/` 一处；
- 与 F4 的 fake-quant PyTorch 参考**逐比特对齐**（逐层中间结果 + 最终图像）；
- 导出 ModelSim 黄金向量：选定层（覆盖每种算子类型至少一层，输入可为裁剪后的小块以控制体积）的输入/权重/输出十六进制向量 + 全网络端到端一组（**256×256 输入**）（v1.1 修订）；
- 位真模拟器跑完整 DDIM 采样得到的最终图像与 fake-quant 参考一致（逐比特或明确记录的例外）。

## 6. Feature 分解与分支策略

每个 feature 一个分支，由独立 agent 执行；项目负责人审查通过、测试全绿后合入 main，再开下一分支。

| # | 分支名 | 内容 | 验收标准 | 依赖 |
|---|---|---|---|---|
| F0 | `feat/project-scaffold` | uv 脚手架、目录结构、pytest、依赖锁定、`.gitignore` 补全 | `uv sync && uv run pytest` 全绿；README 更新使用说明 | — |
| F1 | `feat/fp32-baseline` | L0 基线采样 + 画质关卡 | 两模型样本图与元数据齐备；猫模型 **@256×256（DDIM-50 与 DDIM-20 各 20 张）** 人工验收报告（v1.1 修订） | F0 |
| F2 | `feat/handwritten-unet` | L1 手写 UNet + 手写 DDIM | §5.2 对齐测试全绿 | F1 |
| F3 | `feat/attention-ablation` | L1.5 去注意力实验 | 对比报告 + 签字结论 | F2 |
| F4 | `feat/ptq-export` | PTQ 标定 + 四类 artifact 导出 | INT8 fake-quant 画质验收通过；导出文件齐全且格式说明入库 | F3 |
| F5 | `feat/bittrue-sim` | 位真模拟器 + 黄金向量 | 与 fake-quant 参考逐比特对齐测试全绿；黄金向量导出 | F4 |

**Go/No-go 节点**：F1（画质关卡）、F3（注意力取舍）。任一节点否定结论都会改变后续 feature 的范围，此时先更新本 spec 再继续。

## 8. 与总提案的对应关系

- 本 spec 覆盖总提案 §4（模型路线）、§6（PC 侧工具链中的 `export_ptq.py` / `sim_bittrue.py` / `eval_quality`）、§7 的 M0 行；
- 总提案 v0.2 起 M0 周期为 2~4 周（CPU-only + 原生 256×256 主线）；
- 总提案其余内容（M1 板级、M2 RTL、M3 系统集成）各自后续立项，不在本 spec 约束范围内，但本 spec 的导出格式是 M2 的输入契约。
